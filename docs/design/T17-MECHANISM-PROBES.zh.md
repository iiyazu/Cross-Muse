# T17 信息协作层机制探针（草案，2026-10-12，base 起草，用户提出方向）

> r7 已审定：以 `XMUSE2-PROBES.zh.md` 为准（第 5 节的三个问题已定，S3 改成两个变体，补了产品功能探针和两处 hub 小改动）。本文件保留作为底稿。

取代 T16 草案：不在真实代码库上做实验，而是针对信息层在愿景里承诺的每个功能，各造一个最小、确定、可以自动判定的场景，直接验证。

## 0. 原则
- **玩具世界，不是代码库**：agent 的工作只是按规则维护几个数据项，对错由脚本逐 tick 判定，不依赖个人推理能力。这样噪声小、每次只要几分钟，可以多跑。
- **P 是脚本，不是 LLM**：用 `xmuse send` 以人类身份发消息、决定和取代。两组收到的刺激，文本、时刻、渠道完全相同；唯一差别是 info_layer。plain 组里信息层的字段（kind/scope/supersedes）会被拒绝，所以同一段文本只能作为普通消息发出。
- **三组对照**，避免 xmuse 赢得太轻松：
  - **X**：xmuse，信息层开；
  - **P-dm**：plain，只发给当事人（和 X 相同的渠道）；
  - **P-bc**：plain，同样的文本广播给所有人（强基线：用最笨的办法让每个人都收到）。
  
  P-dm 用来看"没有信息层会怎样"，P-bc 用来看"信息层有没有比群发更好"。
- 执行者用便宜模型（dsh-fl、oc-ms13），不用 Claude。

## 1. 玩具世界
- 数据项 a、b、c、d。每个 tick，驱动脚本在 #team 发一条消息：`tick N: a=…, b=…, c=…, d=…`（数值随机）。
- 规则：每个执行者只为**自己负责**的数据项写文件 `out/<agent>/<key>`，内容是 `N:值`，然后调用 `xmuse_done`。
- 一个 tick 等两个执行者都 done 之后（或超时 90 秒）才发下一个。所以"每 10 秒同步"换成了"每个 tick 都同步"，因为 LLM 一次唤醒本身就要 20–60 秒。
- **判定器**逐 tick 读取 `out/`，按当时**生效的**归属规则，给每个数据项打标：
  - 正确：只有负责人写了，值也对；
  - 越权写：不该写的人写了，旧规则遗留就属于这种；
  - 空缺：没有人写；
  - 值错。

## 2. 场景（每个场景对应一个机制）
| # | 场景 | 刺激（脚本） | 判定 |
|---|---|---|---|
| S1 取代传播（用户的例子） | tick 0 在 #team 发决定："E1 维护 a、b；E2 维护 c、d"。tick 3 **只私信 E1** 一条取代旧决定的新决定："E1 维护 a、c；E2 维护 b、d"。X 组用 `--supersedes`，作用范围继承旧决定。 | tick 3 之后 E2 还写 c 的次数（越权写）、没人写 b 的次数（空缺）、几个 tick 后收敛 |
| S2 新会话后的持久化 | tick 0 发决定（归属规则，外加一条格式约定，例如值要带单位后缀）。tick 4 把两个执行者的会话都换成新会话。 | tick 4 以后的违约率 |
| S3 问答 + 依赖唤醒 | 只私信 E2 一个事实（例如 "d 的值要乘以系数 k=7"）。给 E1 派一个依赖这个事实的任务：E1 维护 d 的派生项 e=d×k，但 E1 不知道 k。 | E1 有没有问、问了谁、答复多久到；e 正确的 tick 占比；X 组的依赖唤醒有没有生效 |
| S4 噪声下的定向信息 | 每个 tick 额外发 5 条与任务无关的闲聊。某一时刻对 module:c 发一条决定（改 c 的格式）。 | 改格式之后 c 的合规率；token 消耗 |
| S5 冲突与时间顺序 | 两次给出相互冲突的规则，后一条取代前一条。plain 组只有消息先后可以参考。 | 是否按最新规则执行 |
| S6 LLM 当 P（真实性检查，可选） | P 是 LLM，目标是"把 c 的负载从 E2 挪给 E1"。 | P 会不会用取代、用得对不对；E2 是否收敛 |

## 3. 指标与次数
- **主要指标**：每个场景定一个，就是表中的判定项。S1 用变更后 5 个 tick 内的越权写加空缺次数。
- **次要指标**：收敛所需的 tick 数、token、唤醒次数、消息条数。
- **次数**：每个场景、每组 10 次。三组交替进行，单次 5–10 分钟。S1 到 S5 总共约 150 次、15–20 小时机器时间，可以分批跑。先做 S1 的试跑：每组 2 次，看刺激有没有送达、判定器是否正确。
- **隔离**：每个 run 的工作区放在临时目录，跑完就移走；另外照旧扫描跨 run 读取。玩具世界里没有答案可抄，泄漏风险低，但仍保留扫描。

## 4. 实现范围
- 驱动脚本 `tools/probe_run.py`：建工作区，`xmuse init`，加两个执行者，按场景脚本发 tick 和刺激（`xmuse send`），等 done、超时，到点换新会话，最后收集数据。
- 判定器 `tools/probe_judge.py`：按场景规则和 tick 记录给 `out/` 打标，输出 json。
- 场景定义 `probes/S1.yaml` … `S5.yaml`：规则、刺激、时刻、判定。
- 汇总 `tools/probe_report.py`：三组的均值和区间，逐 tick 的曲线。
- 先确认 hub 的几个行为：人类发出的决定是否直接生效（不是待确认）；X 组里取代条目是否出现在 E2 下一次唤醒的变更列表里；换新会话的命令。不需要改 hub。
- 放在 prizehub-bench 旁边的一个新的私有目录，或者放在 xmuse2 的 `experiments/` 下。
